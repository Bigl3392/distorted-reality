## URL and state conventions

All resource paths below use /api/v1; the documented separate heartbeat is /healthz.
Use same-origin SPA/API traffic. No dev proxy, port, local launch command or static-directory value is invented.
POST /api/v1/runs/{id}/start returns HTTP 202 with state STARTED as an acknowledgement. STARTED is not added to the persisted state/history enum.
Poll GET /api/v1/runs/{id}; tolerate intermediate states not being observed between polls. The returned history must preserve the permitted sequence, including repeated EXEC_PATH and optional revision/correction.
No polling frequency, overall test timeout, limit value or packet lifetime is set here. Use later owner/operator-approved values; the four-minute target is not an invented hard timeout.
A download-link response supplies a base URL /api/v1/download/<token>. The documented files are its /packet, /journal, /events and /rule children. Do not assume the bare base URL is itself a file.

## Complete, insufficient and failed runs

Persisted sequence:
CREATED → DATASET_LOADED → MRI_DONE → SCAN_DONE → COUNCIL_EVIDENCE → COUNCIL_PATHS → COUNCIL_CRITIC → [COUNCIL_REVISION] → COUNCIL_DECISION → DECISION_RULE_FROZEN → EXEC_PATH (per survivor) → CLAIM_CHECKED → [EXEC_CORRECTION] → PACKET_BUILT → AWAITING_APPROVAL → APPROVED_VIEWED | EXPIRED.
FAILED_CLOSED is an error path from the supported states. label may identify EXEC_PATH_2 while state remains EXEC_PATH.

Freeze these separate fixture scenarios before implementation:
1. Successful complete packet with eligible, distinguishable paths.
2. Completed comparison with tied/insufficient evidence: no preferred path, NO_SUFFICIENT_EVIDENCE shown normally.
3. Fewer than two survivors: FAILED_CLOSED + INCOMPLETE packet per this API contract.
4. Failure before execution: INCOMPLETE with failed_at/failure_reason; packet remains readable/downloadable; approval confirmation refused.
5. Failure after some execution: retain only real sections/receipts, render failed_at/failure_reason and incomplete outcome. Do not claim zero execution/comparison merely from status; see owner question below.
6. Qualitative council recommendation differs from the rule result: both visible, rule stands.
7. Missing median_cycle_min: display absence and the supplied unknowns, never zero or a guessed duration.

State/API fakes must identify themselves as synthetic tests and must never invoke real providers/runner code. Genuine recorded fallback evidence is a separate prerequisite, not something these fakes can create.

## Show / never-show checks

Show verbatim packet claim_statement, synthetic_notice, assumptions, unknowns, did_not_prove and limitations. Preserve both the suppression and scoring-verifiability limitations where supplied.
Always distinguish the synthetic dataset notice from whether an execution is a genuine recorded run.
Scan UI displays overall, fixed generic recommendation and limitations. Validate the full API envelope against scan_result.schema.json; the document's short wording does not authorize dropping required constants/metadata or adding fields.
Never echo question-keyed answers in a response, DOM result, packet or download. Input controls necessarily collect the 15 public answers; do not misclassify the intake request as forbidden result leakage.
Never request/display system-specific scoring, scores, grouping or selection; no hidden debug variation.
Copy checks cover routes/fees, forbidden public names/branding and unsupported business claims through approved scanner inputs. Do not put private deny lists into the test plan/source.
A blanket substring ban on "will improve" would incorrectly reject the required negative claim_statement; use the existing frozen copy criterion and exact required text.
Show meaningful unavailable/refused/expired states for 404/409/410/429/503. An empty recorded list cannot be represented as a successful recorded execution.
